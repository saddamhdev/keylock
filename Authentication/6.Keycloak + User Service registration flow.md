হ্যাঁ — **এইটাই সবচেয়ে common pattern** যখন তুমি **Keycloak** ব্যবহার করো microservice architecture-এ।

সংক্ষেপে flowটা এমন হয়:

```
Create User Request
        │
        ▼
Keycloak (create user)
        │
        ▼
Keycloak returns userId
        │
        ▼
User Service DB (store keycloak_id)
```

---

# 1️⃣ Step-by-Step Flow

### Step 1 — User create request

ধরো admin বা registration API call করলো:

```
POST /users
```

User data:

```
email
name
phone
password
```

---

### Step 2 — User create in Keycloak

Backend first call করে Keycloak Admin API:

```
POST /admin/realms/{realm}/users
```

Example body:

```json
{
 "username": "saddam",
 "email": "saddam@email.com",
 "enabled": true
}
```

Keycloak user create করবে।

---

### Step 3 — Get Keycloak User ID

Keycloak response header থেকে পাওয়া যায়:

```
Location:
.../users/9f8a3c21
```

Keycloak ID:

```
9f8a3c21
```

---

### Step 4 — Save user in service database

User service table:

```
users
------------------------
id
keycloak_id
email
name
phone
```

Example:

```
keycloak_id = 9f8a3c21
```

---

# 2️⃣ Login Flow পরে কেমন হয়

User login করলে:

```
User
 │
 ▼
Keycloak Login
 │
 ▼
JWT Token
 │
 ▼
sub = 9f8a3c21
```

Service token decode করে।

Then query:

```
SELECT * FROM users
WHERE keycloak_id = '9f8a3c21'
```

---

# 3️⃣ Architecture

```
User
 │
 ▼
Keycloak (Authentication)
 │
 ▼
JWT token
 │
 ▼
API Gateway
 │
 ▼
User Service
 │
 ▼
User Database
```

Keycloak = authentication
User Service = business data

---

# 4️⃣ Why this pattern is used

এটা ব্যবহারের কারণ:

✔ password Keycloak manage করে
✔ services password handle করে না
✔ centralized authentication
✔ scalable microservices

---

# 5️⃣ Important Note

Service DB-তে সাধারণত রাখা হয় না:

```
password
otp secret
auth credential
```

এগুলো Keycloak-এ থাকে।
