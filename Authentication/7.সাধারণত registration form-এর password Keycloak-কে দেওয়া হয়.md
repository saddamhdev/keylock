হ্যাঁ 👍 সাধারণত **registration form-এর password Keycloak-কে দেওয়া হয়**, কারণ authentication এবং password management **Keycloak** handle করে।

কিন্তু এটা দুইভাবে implement করা যায়। নিচে দুটো pattern দেখাচ্ছি।

---

# 1️⃣ Pattern 1 — Registration via Keycloak (Recommended)

এখানে password সরাসরি Keycloak-এ যায়।

Flow:

```text id="z24a0d"
User Registration Form
        │
        ▼
Backend API
        │
        ▼
Create user in Keycloak
        │
        ▼
Save business data in User Service DB
```

Example Keycloak API request:

```json id="5w5sn9"
{
 "username": "saddam",
 "email": "saddam@email.com",
 "enabled": true,
 "credentials": [
   {
     "type": "password",
     "value": "123456",
     "temporary": false
   }
 ]
}
```

এখানে password store হবে **Keycloak database-এ (hashed)**।

User service DB-তে password রাখা হবে না।

---

# 2️⃣ Pattern 2 — Keycloak Hosted Registration Page

আরো secure approach হলো Keycloak এর built-in registration page ব্যবহার করা।

Flow:

```text id="50tm3q"
User
 │
 ▼
Keycloak Registration Page
 │
 ▼
Password stored in Keycloak
 │
 ▼
User created
```

তারপর user-service-এ profile তৈরি করা হয়।

---

 │
 ▼

 │
 ▼

 │

Service password verify করে না।

---

# 5️⃣ কেন password Keycloak-এ রাখা ভালো

কারণ Keycloak already দেয়:

* password hashing
* password policy
* brute force protection
* OTP / MFA
* password reset
* account lock

# 🔑 Summary

✔ Registration form-এর password সাধারণত **Keycloak-এ পাঠানো হয়**
✔ Service DB-তে password রাখা হয় না
✔ Service DB শুধু **business user data** রাখে
