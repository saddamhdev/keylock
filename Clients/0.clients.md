You are on the **Clients page in Keycloak**.
This page lists **applications or services that can use Keycloak for authentication**.

Think of a **client** as an **application that asks Keycloak to log in users**.

Example:

```
Web App
Mobile App
Spring Boot API
Admin Console
```

All of these can be **clients**.

---

# 1️⃣ What a Client Is

A **Client = Application registered in Keycloak**.

Example flow:

```
User → Spring Boot App
        ↓
Spring Boot redirects to Keycloak
        ↓
User logs in
        ↓
Keycloak returns JWT token
        ↓
Application allows access
```

So the **application must be registered as a client**.

# 3️⃣ Important Built-in Clients

### account

Allows users to manage their profile.

Example:

```
Change password
Update profile
View sessions
```

---

### account-console

The **frontend UI** for account management.

Example link:

```
http://localhost:6062/realms/myrealm/account
```

---

### admin-cli

Used by **scripts and command line tools** to manage Keycloak.

Example:

```
kcadm.sh
```

---

### realm-management

Contains **admin roles** like:

```
manage-users
view-clients
manage-realm
```

Used internally by Keycloak.

---

### security-admin-console

This is the **admin panel you are currently using**.

Example:

```
http://localhost:6062/admin
```

# 5️⃣ How Clients Work With Authentication

Example login process:

```
User opens Spring Boot app
        ↓
Spring Boot redirects to Keycloak
        ↓
Keycloak login page
        ↓
User enters credentials
        ↓
Keycloak generates JWT token
        ↓
Token returned to client (spring-client)
```

---

# 6️⃣ Example JWT Token Returned

After login Keycloak returns something like:

```json
{
  "preferred_username": "saddam",
  "realm_access": {
    "roles": ["USER"]
  }
}
```

Your backend services use this token to authorize access.
