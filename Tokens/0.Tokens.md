You are viewing **Realm settings → Tokens** in **Keycloak** for your realm `myrealm`.
This page controls **how authentication tokens behave**, including their **security algorithm and expiration times**.

Tokens are the **JWT credentials** issued after a user logs in.

---

# 1️⃣ Default Signature Algorithm

Your setting:

```
RS256
```

This means Keycloak signs JWT tokens using **RSA SHA-256**.

Why it matters:

```
User logs in
   ↓
Keycloak creates JWT
   ↓
Token signed using RS256 private key
   ↓
Spring Boot service verifies token with public key
```

This ensures tokens **cannot be forged or modified**.

---

# 2️⃣ OAuth 2.0 Device Code Lifetime

Your setting:

```
10 minutes
```

This is used in **device login flows**.

Example:

```
Smart TV login
Console login
CLI login
```

User logs in on another device and the device code remains valid for 10 minutes.

# 3️⃣ Access Token Settings

### Access Token Lifespan

Your setting:

```
5 minutes
```

Meaning:

```
JWT token is valid for 5 minutes
```

After 5 minutes the token expires.

Example flow:

```
User login
   ↓
JWT token issued
   ↓
Token valid for 5 minutes
   ↓
API requests allowed
```

After that:

```
Token expired
Client must refresh token
```

---

### Access Token Lifespan for Implicit Flow

Also:

```
5 minutes
```

Implicit flow is used mainly by **browser applications**.

---

### Client Login Timeout

Your setting:

```
1 minute
```

If a user starts login but does not finish within 1 minute, the login request expires.

---

# 4️⃣ Refresh Tokens

Refresh tokens allow users to get a **new access token without logging in again**.

Example:

```
Access Token (5 min)
Refresh Token (longer lifespan)
```

When access token expires:

```
Client sends refresh token
   ↓
Keycloak issues new access token
```

Your setting shows:

```
Revoke Refresh Token → Disabled
```

Meaning refresh tokens can be reused.

In production you often enable this for better security.

---

# 5️⃣ Action Tokens

Action tokens are used for **special user actions**.

Examples:

```
Email verification
Password reset
Account confirmation
```

These tokens are temporary.

---

### User-Initiated Action Lifespan

Your setting:

```
5 minutes
```

If a user clicks a reset password link, it must be used within 5 minutes.

---

### Default Admin-Initiated Action Lifespan

Your setting:

```
12 hours
```

If an admin triggers an action (like reset password), the link remains valid for 12 hours.

---

# 6️⃣ Override Action Tokens

These are specific timeouts for actions like:

| Action             | Purpose                |
| ------------------ | ---------------------- |
| Email verification | Confirm user email     |
| Forgot password    | Reset password         |
| Execute actions    | Admin required actions |

Each action can have its own timeout.

Your microservice architecture likely works like this:

```
User
 ↓

 ↓

 ↓

When token expires:

```

```

---

# 8️⃣ Why Short Token Lifetimes Are Good

Short lifetimes improve security.

Example attack:

```
Attacker steals JWT
```

If token lasts:

```
5 minutes → limited damage
24 hours → big security risk
```

---

```
