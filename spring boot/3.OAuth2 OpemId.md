তুমি যেহেতু **Spring Boot + Microservices** নিয়ে কাজ করো, তাই আমি **OAuth2 এবং OpenID Connect** একটু গভীরভাবে explain করছি—কিন্তু সহজভাবে।

---

# 1️⃣ OAuth2 আসলে কী সমস্যার সমাধান করে

ধরো তুমি একটি app বানালে:

```text
Budget App
```

User চায় তার **Google Drive** access দিতে যাতে app ফাইল পড়তে পারে।

❌ খারাপ উপায়:

```
User → Google username/password → App
```

এটা dangerous।

✔ OAuth2 solution:

```
User → Google login page → Permission → Token → App
```

App শুধু **token পায়**, password না।

এটাই **OAuth 2.0**।

---

# 2️⃣ OAuth2 মূলত Authorization

OAuth2 বলে:

> "এই client কি এই resource access করতে পারবে?"

Example:

```text
Client → Access Account API
```

Token দিয়ে permission check হয়।

---

# 3️⃣ OAuth2 Actors (৪টা main component)

OAuth2 এ চারটা actor থাকে।

| Actor                | Meaning      |
| -------------------- | ------------ |
| Resource Owner       | User         |
| Client               | Application  |
| Authorization Server | Login server |
| Resource Server      | API server   |

Example:

```text
User → React App → Keycloak → Account API
```

এখানে:

* User = resource owner
* React = client
* Keycloak = authorization server
* Account service = resource server

---

# 4️⃣ OAuth2 Grant Types

OAuth2 login করার কয়েকটা method আছে।

| Grant Type         | Use                |
| ------------------ | ------------------ |
| Authorization Code | Web login          |
| Client Credentials | service-to-service |
| Password           | legacy             |
| Refresh Token      | new token          |

Example (microservice):

```
payment-service → account-service
```

এখানে use হয়:

```
client credentials
```

---

# 5️⃣ OpenID Connect কেন দরকার

OAuth2 **identity জানে না**।

Example OAuth2 token:

```
access_token
```

কিন্তু user কে কে?

```
unknown
```

এখানে আসে **OpenID Connect**।

OIDC বলে:

> "এই user কে?"

---

# 6️⃣ OIDC extra token দেয়

OIDC এ তিনটা token থাকে।

| Token         | Use           |
| ------------- | ------------- |
| Access Token  | API call      |
| ID Token      | user identity |
| Refresh Token | renew token   |

Example ID Token payload:

```json
{
 "sub": "12345",
 "name": "Saddam",
 "email": "saddam@mail.com"
}
```

# 9️⃣ JWT Token Structure

Keycloak normally দেয় **JWT token**।

Structure:

```
HEADER.PAYLOAD.SIGNATURE
```

Example payload:

```json
{
 "iss": "http://keycloak/realms/banking",
 "sub": "12345",
 "preferred_username": "saddam",
 "realm_access": {
   "roles": ["CUSTOMER"]
 }
}
```

# 🔟 Service কী করে

Service token verify করে।

Check:

```
signature
issuer
expiration
roles
```

Then API allow।

Example:

```java
@PreAuthorize("hasRole('MANAGER')")
```
