# 1️⃣ What “Users” Means in Keycloak

Users are **people who can log in to your application**.

Examples:

* Customers
* Employees
* Admins
* Managers

Each user has:

* Username
* Email
* Password
* Roles
* Groups
* Attributes

Keycloak stores these and handles **authentication**.

---

# 2️⃣ What Each Column Means

### Username

Unique login name.

Example:

```
saddam
```

Used when logging in.

---

### Email

User email address.

Example:

```
saddam@example.com
```

Used for:

* Password reset
* Email verification
* Notifications

---

### First Name / Last Name

User profile information.

Example:

```
First name: MD
Last name: Saddam
```

These appear in user profile or UI.

---

# 3️⃣ What You Can Do With Users

Click a username (for example **saddam**) and you will see several tabs.

| Tab          | Purpose                |
| ------------ | ---------------------- |
| Details      | Basic user information |
| Credentials  | Set or reset password  |
| Role Mapping | Assign roles           |
| Groups       | Add user to groups     |
| Sessions     | View active sessions   |
| Attributes   | Store custom data      |

---

# 4️⃣ Example User Authentication Flow

When a user logs in:

```
User → Login form
       ↓
Keycloak verifies username + password
       ↓
Keycloak creates session
       ↓
JWT token generated
       ↓
User accesses application
```

Your Spring Boot services will use that **JWT token**.

---

# 5️⃣ Example Role Assignment

For example:

User:

```
saddam
```

Role:

```
ADMIN
```

Now only admins can access certain APIs.

Example in Spring Boot:

```java
@PreAuthorize("hasRole('ADMIN')")
```

# 6️⃣ User Management by Admin

Admins can:

* Create users
* Disable accounts
* Reset passwords
* Assign roles
* Force logout

Example:

```
Users → saddam → Credentials → Reset Password
```
