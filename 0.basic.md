## 🔐 What is **Keycloak**?

**Keycloak** is an **open-source Identity and Access Management (IAM)** system.

In simple words 👉

> It handles **login, signup, roles, permissions, tokens, SSO**, so you **don’t write auth logic yourself**.

---

## 🧠 Why Keycloak is used in real projects

Without Keycloak 😵

* You manually handle login
* Password hashing
* JWT creation
* Role checking
* Social login
* Token refresh
* Security bugs risk

With Keycloak 😌

* All handled centrally
* Industry-standard security
* Works with **Spring Boot, React, Angular, Mobile, Microservices**

## 🧩 Core Concepts (must understand)

### 1️⃣ Realm

A **Realm = security boundary**

Example:

* `banking-realm`
* `training-realm`

Each realm has its own:

* Users
* Roles
* Clients

---

### 2️⃣ User

Actual person or system account.

Fields:

* username
* email
* password
* roles

---

### 3️⃣ Role

Authorization logic.

Types:

* **Realm Role** → global
* **Client Role** → app-specific

Example:

```
ADMIN
USER
AUDITOR
```

---

### 4️⃣ Client (VERY IMPORTANT)

A **Client = your application**

Examples:

* Spring Boot backend
* React frontend
* Mobile app

Client types:

* **Public** → frontend apps
* **Confidential** → backend services
* **Bearer-only** → API only

---

### 5️⃣ Token (JWT)

Keycloak issues:

* **Access Token**
* **Refresh Token**
* **ID Token**

JWT contains:

```json
{
  "sub": "user-id",
  "preferred_username": "saddam",
  "roles": ["ADMIN"],
  "exp": 1700000000
}
```

## 🔄 Login Flow (Simple)

1️⃣ User opens frontend
2️⃣ Redirected to Keycloak login
3️⃣ User logs in
4️⃣ Keycloak returns token
5️⃣ Frontend calls backend with token
6️⃣ Backend validates token

---
