You are viewing the **Client Scopes** page in **Keycloak**.
Client scopes control **what information (claims) is included inside the JWT token** that Keycloak issues after login.

Think of a **client scope** as a **set of fields added to the token**.

---

# 1️⃣ What a Client Scope Is

When a user logs in, Keycloak creates a **JWT access token**.

Example token payload:

```json
{
  "sub": "12345",
  "name": "Saddam",
  "email": "saddam@example.com",
  "realm_access": {
    "roles": ["USER"]
  }
}
```

The **client scopes decide which fields appear in this token**.

---

# 2️⃣ Columns in Your Screenshot

| Column        | Meaning                    |
| ------------- | -------------------------- |
| Name          | Scope name                 |

---

# 3️⃣ Default vs Optional Scopes

### Default

Always included in tokens.

Example:

```
profile
email
basic
```

Meaning every login token contains these claims.

---

### Optional

Included only if requested.

Example:

```
phone
address
offline_access
```

Applications must request them explicitly.

Example request:

```
scope=openid profile email phone
```

---

# 4️⃣ Important Scopes in Your List

### profile

Adds user profile info:

```
name
family_name
given_name
preferred_username
```

---

### email

Adds:

```
email
email_verified
```

---

### address

Adds address information.

Usually used for:

```
shipping
billing
identity verification
```

---

### phone

Adds phone number fields.

Example:

```
phone_number
phone_number_verified
```

---

### offline_access

Allows applications to request **refresh tokens that work even when the user is offline**.

Common use cases:

```
mobile apps
long-running services
background tasks
```

---

### microprofile-jwt

Used by **MicroProfile applications** (Java enterprise environments).

Not always required in Spring Boot setups.

---

### organization

Adds organization-related attributes.

Useful in **multi-tenant systems**.

---

# 5️⃣ How Client Scopes Affect Your Application

Example login:

```
User → Keycloak login
      ↓
Token generated
```

Token might contain:

```json
{
  "preferred_username": "saddam",
  "email": "saddam@example.com",
  "roles": ["USER"]
}
```

Your **Spring Boot microservices** read these fields.

Example:

```java
Jwt jwt = (Jwt) authentication.getPrincipal();
String email = jwt.getClaim("email");
```

---

# 6️⃣ Where Client Scopes Are Used

Client scopes are attached to **clients**.

Example client:

```
spring-boot-app
```

Configuration:

```
Clients → spring-boot-app → Client scopes
```

Then attach:

```
profile
email
roles
```

# 7️⃣ Example Architecture in Your System

```
User
 ↓

 ↓
JWT token issued
 ↓
API Gateway

```

Client scopes determine **what user information appears in that JWT token**.

---

# 8️⃣ Best Practice for Spring Boot Microservices

Most projects use:

```
openid
profile
email
roles
```

These provide enough information for authentication and authorization.
