যদি **user data অন্য কোনো system-এর database এ থাকে**, তাহলে Keycloak ব্যবহার করার সময় সাধারণত ৩টা architecture ব্যবহার করা যায়। কোনটা ব্যবহার করবে তা depend করে system design-এর উপর।

আমি সহজভাবে explain করছি।

---

# 1️⃣ Option 1 — User Federation (LDAP / AD)

যদি user data থাকে:

* LDAP
* Active Directory
* Corporate Directory

তাহলে **Keycloak** এর **User Federation** ব্যবহার করা হয়।

Flow:

```
User
 │
 ▼
Keycloak
 │
 ▼
LDAP / Active Directory
 │
 ▼
Authentication
 │
 ▼
Keycloak JWT token
```

এখানে Keycloak user database রাখে না।

---

# 2️⃣ Option 2 — Custom User Storage Provider (Important)

যদি user data থাকে **custom application database এ** (যেমন Spring Boot user-service DB), তখন ব্যবহার করা হয়:

```
Keycloak User Storage SPI
```

Keycloak plugin লিখে external database connect করা যায়।

Architecture:

```
User
 │
 ▼
Keycloak
 │
 ▼
Custom User Storage Provider
 │
 ▼
External User Database
```

এটা enterprise system এ খুব common।

---

# 3️⃣ Option 3 — Login via External API

আরেকটা architecture আছে।

তুমি authentication অন্য service দিয়ে করাও।

Example:

```
User
 │
 ▼
Auth Service
 │
 ▼
User Database
 │
 ▼
Keycloak token
```

কিন্তু এটা OAuth / OIDC flow redesign করতে হয়।

---

# 4️⃣ Most Common Pattern (Microservices)

ধরো তোমার system:

```
user-service
account-service
payment-service
```

User DB আছে user-service এ।

Best pattern:

```
Keycloak
   │
   ▼
Keycloak DB (users)
   │
   ▼
user-service (business data)
```

মানে:

* authentication → Keycloak
* user business data → user-service

---

# 5️⃣ Real Enterprise Example

```
Users
 │
 ▼
Keycloak
 │
 ├─ Local DB
 ├─ LDAP Federation
 └─ Custom User Storage SPI
 │
 ▼
JWT Token
 │
 ▼
Microservices
```

---

# Summary

যদি user data অন্য system এ থাকে:

| Situation            | Solution          |
| -------------------- | ----------------- |
| LDAP / AD            | User Federation   |
| Custom DB            | User Storage SPI  |
| Another Auth Service | Identity Provider |

---

✔ সাধারণ microservice project এ best practice:

```
Authentication → Keycloak
User profile data → user-service
```
