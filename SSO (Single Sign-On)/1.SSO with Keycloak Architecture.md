# 1️⃣ Keycloak কি?

**Keycloak** হলো একটি **Open Source Identity and Access Management (IAM)** system।

এটা handle করে:

* Authentication (Login)
* Authorization (Role / Permission)
* SSO
* User management
* Social login
* Token management

# 3️⃣ Login Flow (Step by Step)

### Step 1

User opens application

```
https://app.com
```

---

### Step 2

Application redirects user to **Keycloak Login Page**

```
https://keycloak/auth
```

User enters:

* username
* password

---

### Step 3

Keycloak verifies user from database.

Keycloak database normally stores:

```
USER
ROLE
GROUP
CREDENTIAL
SESSION
```

---

### Step 4

Keycloak generates **JWT Token**

Example:

```
access_token
refresh_token
id_token
```

---

### Step 5

Token returned to client.

Example:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

---

### Step 6

Client sends request with token.

```
GET /users

Authorization: Bearer TOKEN
```

---

### Step 7

Gateway verifies token.

```
Spring Cloud Gateway
        ↓
JWT validation
        ↓
Forward request
```

---

### Step 8

Microservices read token

Example:

```
UserService
AccountService
LoanService
```

Each service can read:

```
userId
roles
permissions
email
```

from JWT.

---

# 4️⃣ SSO Flow (Multiple Applications)

Imagine company has multiple apps:

```
HR System
Loan System
Admin Panel
Analytics Dashboard
```

User logs in once.

```
User
 ↓
Keycloak Login
 ↓
Session Created
```

Now user can access:

```
HR System
Loan System
Admin Panel
```

without login again.

This is **SSO**.

# 5️⃣ Keycloak Components

### Realm

Realm = Security domain.

Example:

```
banking-realm
ecommerce-realm
company-realm
```

Each realm has:

* users
* roles
* clients

---

### Client

Client = Application.

Example:

```
gateway-service
frontend-app
mobile-app
admin-panel
```

---

### Roles

Authorization control.

Example:

```
ADMIN
MANAGER
USER
AUDITOR
```

---

### Users

Example:

```
saddam
rahim
karim
```

# 7️⃣ Token Example (JWT)

Decoded token:

```
{
  "sub": "user-id",
  "email": "user@gmail.com",
  "preferred_username": "saddam",
  "realm_access": {
      "roles": ["ADMIN"]
  }
}
```

Microservices read this data.

# 8️⃣ Microservice Security Flow

```
User
 ↓
Login
 ↓
Keycloak
 ↓
JWT Token
 ↓
API Gateway
 ↓
Microservices
```

Each request includes:

```
Authorization: Bearer TOKEN
```

---

# 9️⃣ Spring Boot Integration

Spring Boot service config:

```
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: http://localhost:8080/realms/banking
```

Then Spring automatically validates token.
