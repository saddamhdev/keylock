You are in **Realm Settings → Keys** in **Keycloak** for your realm `myrealm`.
This page shows the **cryptographic keys Keycloak uses for security**.

These keys are used for:

* **Signing JWT tokens**
* **Encrypting tokens or data**
* **Verifying token authenticity**

---

# 1️⃣ Why Keys Are Important

When a user logs in:

```
User → Keycloak login
        ↓
Keycloak creates JWT token
        ↓
Token is cryptographically signed
```

Your **Spring Boot services verify the token signature** using Keycloak’s public key.

This ensures:

* tokens are authentic
* tokens were issued by Keycloak
* tokens were not modified

# 5️⃣ Where Applications Get the Public Key

Spring Boot services automatically fetch it from:

```
http://localhost:6062/realms/myrealm/protocol/openid-connect/certs
```

This endpoint provides all public keys.

---

# 6️⃣ Token Verification Flow

```
User login
   ↓
Keycloak issues JWT token
   ↓
Token signed with RS256 private key
   ↓
API Gateway / Microservice receives token
   ↓
Service fetches public key from Keycloak
   ↓
Signature verified
```

If verification fails → request rejected.

---

# 7️⃣ Why This Is Secure

Because:

* Private key stays inside Keycloak
* Only public key is shared
* Attackers cannot forge tokens

---

# 8️⃣ Example Spring Boot Configuration

Your service will verify tokens using:

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: http://localhost:6062/realms/myrealm
```

Spring Boot automatically loads the keys.

---

# 9️⃣ Key Rotation

Keycloak automatically supports **key rotation**.

Meaning:

```
Old key → replaced with new key
```

Tokens issued with old keys still work until expiration.
