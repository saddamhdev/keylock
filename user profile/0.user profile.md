You are in **Realm settings → Client policies → Profiles** in **Keycloak**.
This section defines **security profiles that control how clients (applications) must behave when using OAuth2 / OpenID Connect**.

Think of a **Client Profile** as a **security rule template for applications that connect to Keycloak**.

---

# 1️⃣ What Client Profiles Do

When an application registers as a **client**, these profiles can enforce rules like:

* required authentication method
* allowed token algorithms
* allowed redirect URIs
* OAuth security requirements

Example rule:

```id="u6j5kq"
Client must use PKCE
Client must use HTTPS
Client must use signed tokens
```

This prevents insecure client configurations.

---

# 2️⃣ Profiles You See in Your Screenshot

These are **built-in security profiles** provided by Keycloak.

### FAPI Profiles

Example:

```id="6um06n"
fapi-1-baseline
fapi-1-advanced
fapi-ciba
```

FAPI = **Financial-grade API security standard**.

These are used by:

* banks
* financial systems
* open banking APIs

They enforce **very strict OAuth security rules**.

Example requirement:

```id="wzw8go"
PKCE mandatory
Mutual TLS
Signed requests
```

---

### OAuth 2.1 Profiles

Examples:

```id="79ks24"
oauth-2-1-for-confidential-client
oauth-2-1-for-public-client
```

These enforce **OAuth 2.1 security recommendations**.

Example restrictions:

```id="gd42oo"
Implicit flow disabled
PKCE required
Secure redirect URIs
```

---

### FAPI 2 Profiles

Examples:

```id="hyhzpi"
fapi2-security-profile
fapi2-message-signing
fapi2-dpop-security-profile
```

These are newer **financial API security specifications**.

Used in **high-security financial environments**.

---

### SAML Security Profile

Example:

```id="a8aqb3"
saml-security-profile
```

Used if applications authenticate using **SAML instead of OpenID Connect**.

---

# 3️⃣ Why Client Policies Exist

Without policies, developers could accidentally configure insecure clients.

Example bad configuration:

```id="oml2jy"
HTTP redirect URI
Weak token algorithm
No PKCE
```

Policies enforce **security best practices automatically**.

---

# 4️⃣ Example Client Security Enforcement

Example policy:

```id="mpfeek"
Profile: oauth-2-1-for-public-client
```

Keycloak will enforce:

```
PKCE required
Implicit flow disabled
Secure redirect URIs only
```

This protects the authentication system.

---

# 5️⃣ When These Are Used

These profiles are used mainly for:

| Use case                | Profile       |
| ----------------------- | ------------- |
| Banking APIs            | FAPI          |
| Modern OAuth security   | OAuth 2.1     |
| Government / fintech    | FAPI 2        |
| Enterprise SAML systems | SAML security |

---

# 6️⃣ Do You Need This Now?

For most development projects:

```id="v1wtiz"
You do NOT need to change anything here
```

Keycloak already provides secure defaults.

You only configure these if:

* building open banking APIs
* enforcing OAuth security standards
* running enterprise IAM policies

---

# 7️⃣ Typical Setup for Spring Boot Microservices

Usually developers simply:

```
Create realm
Create client
Create roles
Configure Spring Security
```

Client policies remain **default**.

---

# 8️⃣ Example Architecture for Your Project

Your system likely looks like:

```
User
 ↓
Frontend / Gateway
 ↓
Keycloak
 ↓
JWT Token
 ↓
Spring Boot Microservices
```

Client policies simply ensure the **applications connecting to Keycloak are secure**.
