You are in **Realm Settings → User Registration → Default Roles** in **Keycloak** for your realm `myrealm`.

This page controls **which roles are automatically assigned to a user when the user is created or registers**.

---

# 1️⃣ What “Default Roles” Mean

When a **new user is created**, Keycloak automatically gives them certain roles.

Example flow:

```
New user registers
      ↓
Keycloak creates account
      ↓
Default roles automatically assigned
```

So you **do not need to manually assign those roles every time**.

---

# 2️⃣ Roles You Currently Have

Your screenshot shows these default roles:

| Role                   | Purpose                                    |
| ---------------------- | ------------------------------------------ |
| account:view-profile   | Allows user to view their profile          |
| account:manage-account | Allows user to edit their account          |
| uma_authorization      | Used for advanced authorization features   |
| offline_access         | Allows refresh tokens when user is offline |

These are **built-in Keycloak roles**.

---

# 3️⃣ What Each Role Does

### account:view-profile

Allows users to access:

```
Account console → Profile page
```

Example:

```
http://localhost:6062/realms/myrealm/account
```

Users can see their profile information.

---

### account:manage-account

Allows users to:

```
Change password
Update profile
Manage sessions
```

This is required for **self-service account management**.

---

### uma_authorization

UMA = **User Managed Access**

It is used for advanced authorization models where users control access to resources.

Most applications **do not use this initially**.

---

### offline_access

Allows applications to request **offline refresh tokens**.

Example:

```
Mobile app login
Access continues even when user is not actively logged in
```

Useful for long-running sessions.

---

# 4️⃣ Why Default Roles Are Useful

Without default roles:

```
Create user
↓
Admin manually assigns roles
```

With default roles:

```
Create user
↓
Roles assigned automatically
```

This simplifies user management.

---

# 5️⃣ Example in Your Application

If a user registers:

```
username: saddam
```

Keycloak will automatically give:

```
account:view-profile
account:manage-account
```

Then the user can manage their own account.

---

# 6️⃣ Assigning Your Own Default Roles

You can add roles like:

```
USER
CUSTOMER
EMPLOYEE
```

Steps:

```
Assign role → select role
```

Example:

```
USER
```

Now every new user will automatically have **USER role**.

---

# 7️⃣ Typical Setup in Real Applications

Most systems define:

```
USER
ADMIN
MANAGER
```

Then set:

```
Default role = USER
```

So every new user becomes a **normal user**.

---

# 8️⃣ How This Works With JWT Tokens

When a user logs in, the roles appear in the **JWT token**.

Example token:

```json
{
  "realm_access": {
    "roles": [
      "USER"
    ]
  }
}
```

Your Spring Boot APIs read these roles for authorization.

Example:

```java
@PreAuthorize("hasRole('USER')")
```

---
