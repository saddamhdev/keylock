You are viewing **Realm Roles** in **Keycloak** for your realm (`myrealm`).
Realm roles define **permissions that apply across the entire realm** (all applications/clients inside that realm).

Let’s break down what you see.

---

# 1️⃣ What “Realm Roles” Are

A **role** represents a **permission or authority**.

Example:

| Role    | Meaning                   |
| ------- | ------------------------- |
| ADMIN   | Full system access        |
| USER    | Normal application user   |
| MANAGER | Manager-level permissions |

When a user logs in, Keycloak adds their roles to the **JWT token**, and your application uses those roles for authorization.

Example in a Spring Boot service:

```java
@PreAuthorize("hasRole('ADMIN')")
```

Only users with the **ADMIN** role can access that endpoint.

# 2️⃣ Roles Visible in Your Screenshot

You currently have **5 roles**.

### ADMIN

```
Administrator role
```

Used for system administrators.

---

### USER

```
Regular application user
```

Used for normal users.

These two roles are usually **custom roles you created**.

---

### default-roles-myrealm

This is an **automatic Keycloak role group**.

```
Composite: True
```

Meaning it **contains multiple roles inside it**.

When a new user is created, Keycloak automatically assigns this default role.

---

### offline_access

Allows applications to **refresh tokens even when the user is offline**.

Example:

```
Mobile apps
Long-running background tasks
```

---

### uma_authorization

Used for **User-Managed Access (UMA)**.

This is an advanced authorization feature that allows users to control access to their resources.

Most applications **don’t use this initially**.

---

# 3️⃣ What “Composite” Means

You see a column:

```
Composite
```

If it is **True**, it means the role contains other roles.

Example:

```
ADMIN
 ├── USER
 ├── MANAGE_USERS
 └── VIEW_REPORTS
```

Assigning **ADMIN** automatically grants those child roles.

---

# 4️⃣ How Roles Are Used

Roles are assigned to:

* Users
* Groups
* Clients

Example:

```
User: saddam
Role: ADMIN
```

Now that user has admin permissions.

---

# 5️⃣ How Roles Appear in JWT Token

When a user logs in, Keycloak issues a **JWT token** like:

```json
{
  "realm_access": {
    "roles": [
      "ADMIN",
      "USER"
    ]
  }
}
```

Your Spring Boot services read these roles to allow or deny access.

# 6️⃣ Example for Your Microservices

Your architecture might look like:

```

 ↓

 ↓
JWT token with roles
 ↓
API Gateway

```

Example access rules:

| Endpoint      | Required Role |
| ------------- | ------------- |
| /admin/users  | ADMIN         |
| /account/view | USER          |
| /transactions | USER          |
